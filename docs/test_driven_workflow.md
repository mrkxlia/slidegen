# テスト駆動でslidegenを拡張する

社内 Claude Code が新しい型を追加するときの作業フロー。
**実装前にテストとサンプルから入る**ことで「意図したものになっているか」を継続的にチェックする。

## ループ全体図

```
   ┌────────────────────────────────────────────────────┐
   │  1. 型を発案（Web/画像/pptx見て、必要性を判断）         │
   │  2. make new で雛形を生成 ─────┐                    │
   │  3. サンプル記法(.slide)を仕上げる │ 雛形は先に出る    │
   │  4. レンダラ(render_*.py)のTODOを埋める               │
   │  5. make check ────────────────┐                    │
   │      ├─ pytest (第1層): 構造の自動チェック            │
   │      └─ モンタージュ生成 (第2層): 目視チェックリスト  │
   │  6. モンタージュを見て意図と合っているか確認 (第3層)    │
   │      └─ 違えば 3 か 4 に戻る                           │
   │  7. system_prompt.md に新型の書式を追記                │
   └────────────────────────────────────────────────────┘
```

## 第1層：構造インバリアント（自動）

`tests/test_invariants.py` で全サンプルを通す。確認内容:

| ID | 何を見る | 違反したとき意味すること |
|----|---------|----------|
| E1 | テキストがネイティブのテキストフレームに入っている | 編集可能性が壊れた (§2-bis) |
| E2 | 画像だけのスライドが無い | 同上 |
| E3 | シェイプ種別がネイティブ | 同上 |
| P1 | 塗り色が theme パレット内 | デザイン制約 §3-1 違反、独自色を作っている |
| P2 | accent色の面積比 ≤ 8% | 強調が暴走 (§3 揃える/減らす) |
| S1 | シェイプがスライド境界内 | レイアウト計算バグ |
| S2 | 1スライドのシェイプ数 < 80 | 暴走防止 |
| F1 | フォントが theme.font に統一 | デザイン制約 §3-1 違反 |

実行: `make test`

## 第2層：モンタージュ目視（半自動）

`tools/visual.py` で記法→pptx→画像化→モンタージュを1コマンドで生成。
モンタージュを開いて、出力に表示されるチェックリストを見ながら確認。

実行: `make visual` （全サンプル）または `make check TYPE=mytype` （新型のみ）

## 第3層：意図との一致（人間）

機械的に判定できない最終確認。モンタージュを見て:
- 「言いたいこと」が見た瞬間に伝わるか
- 違う型のほうが適切ではないか

これは Claude Code が判断するべきではなく、最終確認は人間（エックスさん）が行う。
ただ、`make check` の出力には常にこの観点もチェックリストとして表示される。

## 新型を追加する：実例

「じょうろ型ピラミッド（pyramid_inverted）」を足すケース。

### ステップ1: 雛形を生成

```bash
make new TYPE=pyramid_inverted \
         INTENT="下位ほど規模が小さいピラミッド" \
         LAYOUT=columns COUNT="3..5"
```

これで以下が自動生成される:
- `type_specs/pyramid_inverted.json` — 型スペック
- `slidegen/render_pyramid_inverted.py` — レンダラ雛形（TODO付き）
- `examples/pyramid_inverted.slide` — サンプル記法のスケルトン
- `slidegen/__init__.py` に登録を追加

### ステップ2: サンプル記法を仕上げる

`examples/pyramid_inverted.slide` を編集して「この型で表現したいこと」を書く。
**先にサンプルから書く**ことで、何を作るべきかが明確になる。

### ステップ3: レンダラを実装

`slidegen/render_pyramid_inverted.py` の `TODO` を埋める。
規約:
- 色は `theme.rgb("xxx")` 経由のみ。新色を直値で書かない
- 強調は accent のみ（`blk.highlight` で判定）
- 配置は `add_rect / add_text / add_hline` を使う
- 座標は EMU の int を保証（`int(...)` で包む）

### ステップ4: 検証

```bash
make check TYPE=pyramid_inverted
```

これで第1層 pytest が走り、続いて第2層モンタージュが生成される。
モンタージュを開いて目視確認。違和感があればステップ2か3に戻る。

### ステップ5: system_prompt.md を更新

新型をAIが選べるように、`docs/system_prompt.md` の判断テーブルと型一覧に1行足す。

## よくある第1層エラーと対処

### P1: パレット外の色が使われている
→ レンダラで直値の hex を書いていないか確認。必ず `theme.rgb("...")` を経由。

### P2: accent比率が8%超過
→ accent を使う要素を1つだけに絞る。残りは main / main_2 / main_3 を使う。
   背景や大面積に accent を塗っていないか確認（背景はベース、強調だけが accent）。

### S1: シェイプがスライド境界外
→ レイアウト計算で座標がスライド範囲を超えていないか。エッジケース（要素数1個や端の要素）で
   `cx - width/2 < MARGIN` のようなアンダーフローが起きやすい。境界クランプを入れる。
   またコネクタは float 座標を受け付けない → `int(x), int(y)` で囲むこと。

### E系: 編集可能性違反
→ 画像を生成・挿入していないか。テキストは必ず add_text を経由しているか。
