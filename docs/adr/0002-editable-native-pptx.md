# 0002. 出力は編集可能なネイティブ pptx とし、画像化しない

- ステータス: 採用 (Accepted)
- 日付: 2026-06-28
- 関連: [docs/ppt_design_doc.md §2-bis](../ppt_design_doc.md), `slidegen/render.py`, `slidegen/theme.py`

> 本 ADR は設計ドキュメント [ppt_design_doc.md](../ppt_design_doc.md) §2-bis の決定を、発見しやすいよう
> ADR として**要約**したもの（詳細・チェックリストは §2-bis を正とする）。

## コンテキスト

AI に直接スライドを作らせると、HTML を画像化する/絵を描かせる等の手段では **1枚絵になり一切編集できない**。
本システムの目的は「安定して・速く・**修正可能な形で**」スライドを作ることであり、最終成果物が編集可能で
あることは手段の選択を根本から規定する。

## 決定

**最終成果物は、PowerPoint で開いてテキスト・図形・色を自由に編集できるネイティブ `.pptx` でなければならない。**
パーサー（`render.py`）は記法を、PowerPoint が理解できるネイティブ要素へ翻訳する。**画像には絶対にしない。**

編集可能性ルール（§2-bis の5原則）:

1. テキストは必ず**テキストフレーム**に入れる（打ち直せる）。
2. 可能な限り **potx のプレースホルダ**へ流し込む（レイアウト/アウトライン編集・テーマ追従）。
3. 色・フォントは**テーマ参照**で指定（直値ハードコードを避け、`theme.py` 経由。テーマ変更で全スライド追従）。
4. 図形は**ネイティブシェイプ**（Rectangle / Line / コネクタ）で作る。
5. 表は**本物の PowerPoint テーブル**（`add_table`）で作る。

## 結果

良い点:

- PowerPoint 上での部分修正・再利用が可能（運用に耐える）。
- 「色・フォントはテーマ参照」が**デザイン制約（R1）と編集可能性を同時に**担保する。
- 構造インバリアントのテスト（`tests/test_invariants.py`）で規約を常時監視できる。

トレードオフ:

- HTML→画像のような**任意のビジュアル表現はできない**。表現は型カタログの範囲に収まる。これは
  3層責任分界（内容/構造/見せ方を分離）に基づく**意図的な制約**であり、レイアウト崩れ・装飾過多を防ぐ。

## 検討した代替案

- **画像出力（AI に絵/HTML を描かせ画像化）**: 編集不可のため却下。
- **色・フォントの直値ハードコード**: テーマ追従できずデザイン制約が崩れるため不可（テーマ参照に限定）。
