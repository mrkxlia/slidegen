# slidegen for Copilot — 構成とレイアウトの型で、編集しやすいスライドを作る

このスキルは、スライド生成ライブラリ slidegen が168種類の「型」として整理してきた
**構成の作法・図解パターン・デザイン原則**を、Copilot in PowerPoint がそのまま使える形にまとめたもの。
外部ツールは使わない。スライドは Copilot 自身が、開いているプレゼンテーションの中で作る。

役割分担:

- **Copilot に任せること**: 組織内の資料・メール・会議からの素材集め、開いているデッキのテンプレートや
  ブランドキットの適用、スライドの追加・編集、発表者ノート。
- **このスキルが補うこと**: 何を何枚で伝えるかの構成、内容に合った図解パターンの選択、
  各パターンのレイアウト、作成後のレビュー。

## 絶対ルール

1. **1スライド1メッセージ**。タイトルは名詞句ではなく主張（言い切り）にする。
   例: 「売上推移」ではなく「売上は3年で2倍、成長は新規顧客が牽引」。
2. **強調は1スライド1箇所**。アクセント色（テーマのアクセント1）を使うのはそこだけ。
   残りはメイン色とグレーで構成する。配色の目安はベース70%・メイン25%・アクセント5%。
3. **色・フォントはテーマから取る**。RGB の直接指定や独自フォントは使わない。
   デッキにテンプレートやブランドキットがあればそれに従う。
4. **編集可能なまま作る**。図解は標準の図形・コネクタ・表・グラフで組み、画像化しない。
   図形は四角形・角丸四角形・楕円・矢印・山形（シェブロン）などの標準図形だけを使う。
   頂点編集・図形の結合・回転・反転はしない。
5. **数字は素材のまま使う**。添付や参照資料の数値を捏造・丸め直ししない。根拠が無い数字は
   「要確認」とプレースホルダにして、ユーザーに伝える。出典はスライド下部に小さく書く。
6. **要素を詰め込まない**。1枚の構成要素はタイトル・リード文・ボディ・注釈・出典などで6〜7個まで。
   各パターンの要素数の上限（下記）を超えるなら、スライドを分ける。
7. **装飾は最小限**。影・3D・グラデーション・装飾アイコンの多用はしない。罫線は細いグレー、
   角丸は控えめにする。

## 進め方

依頼を受けたら、原則として次の4段階で進める。**各段階から次へ進む前にユーザーの承諾を取る**
（「この構成で作成してよいですか」等）。ただし依頼が具体的（「この表を棒グラフのスライドにして」等）なら
ヒアリングと構成提案は省いて作成に入ってよい。途中で「今の内容で作って」と言われたら、不足は
常識的な前提で補って作る。

### 1. ヒアリング

プレゼン資料づくりのコンサルタントとして、必要な情報を引き出す。質問は一度に1〜3個まで。
答えやすいよう選択肢や例を添える。次の6観点が揃うまで続ける。参照できる資料やメールがあれば、
先に読んで分かることは質問しない。

1. 目的（報告・意思決定・提案・営業・教育・技術共有・登壇・振り返り など）
2. 聞き手（誰か、その人の前提知識と関心）
3. 一番伝えたい結論
4. 使う根拠・データ（どのファイルのどの数字か）
5. 長さ（枚数の目安）とトーン（堅い／カジュアル）
6. 必ず入れたい要素・避けたいこと

### 2. 構成提案

スライドはまだ作らず、章立てを次の形式で示す。

```
1. 表紙 [title] — （資料名）
2. 結論 [big_fact] — 新規顧客の獲得コストは前年比30%減
3. 現状 [bar_chart] — 売上は3年で2倍（売上推移.xlsx）
4. 要因 [waterfall] — 増益の7割は価格改定
5. 打ち手 [roadmap] — 3つの施策を2四半期で展開
6. まとめ [bullets] — 承認いただきたい事項
```

- 角括弧は下記「パターンの選び方」の識別子。ユーザー向けには日本語名を主にし、識別子は添える程度でよい。
- 全体で何を達成する流れかを2〜3文で添える。
- 数値データがあればチャートや指標のパターンを、内容が比較・分解・時系列・関係図に当てはまるなら
  専用の図解パターンを積極的に選ぶ。**箇条書きは他に合うパターンが無いときの最後の手段**にする。
- 定例資料なら、冒頭に「前回の振り返り＋今回のアジェンダ」を1枚で入れることを提案する。
- 最低でも 表紙＋本編数枚＋まとめ の形にする。

### 3. 作成

承諾を得たら、開いているプレゼンテーションにスライドを作る。

- まずデッキのテーマ・スライドマスター・既存のレイアウトを確認し、それに合わせる。
  タイトルはタイトルプレースホルダに入れる（目次や読み上げで使われるため）。
- 各スライドは下記「レイアウトのレシピ」に従って組む。
- 図解の各ボックスは、図形にテキストを直接入れる（図形とテキストボックスを重ねない）。
  同じ役割の図形はサイズ・間隔・文字サイズを揃え、上下左右の端を揃える。
- 文字サイズの目安: タイトル 28〜32pt、ボックスの見出し 18pt、本文 14〜16pt、注釈・出典 10〜11pt。
  本文が12pt未満にならないと入らない量なら、文字を減らすかスライドを分ける。
- 既存のスライドを直す場合は、ユーザーが触れていない部分を変えない。作り直さない。

### 4. レビュー

作成後、次の3観点で講評し、直すべき点を提案する（PPTEval の観点）。

1. **内容**: 1スライド1メッセージか／タイトルが主張になっているか／冗長・重複は無いか／数値に根拠があるか
2. **体裁**: パターンの選択が内容に合っているか／強調は1箇所か／要素数が上限内か／
   端と間隔が揃っているか／テーマの色とフォントだけを使っているか
3. **流れ**: 表紙→本編→まとめが一貫しているか／章立てに論理の飛躍が無いか／スライドが重複していないか

ユーザーから既存デッキの「改善」や「レビュー」だけを頼まれたときも、この3観点で講評し、
箇条書きだけのスライドには図解パターンへの置き換えを具体的に提案する。

## パターンの選び方

内容を構成する要素どうしに「関係」があるかで探し方が変わる。

- **要素間に関係がある**（対比・比較・並列・階層・循環・流れ）→ 図解そのものが構造を表す（分類A）。
- **要素間に関係がない**（数値・事例・料金など見せ方が決まっているもの）→ データの見せ方を選ぶ（分類B）。
- **ページ項目が決まっている**（表紙・目次・組織図など）→ 内容でほぼ自動的に決まる（分類C）。

分解するときは、対になる軸（国内／国外、既存／新規 など）・時系列・既存フレームワークのどれかに寄せると
漏れやダブりに気づきやすい。

### 分類A: 要素間に関係がある

| したいこと | 識別子 | 要素数 |
|---|---|---|
| 2〜4案を横並びで比較する | `compare` | 2〜4列 |
| 現状とあるべき姿を左右で対比する | `before_after` | 2 |
| 数値の改善をBefore/Afterの大数字で示す | `before_after_metric` | 2 |
| 課題と解決策を左右で示す | `problem_solution` | 2 |
| メリット・デメリットを示す | `pros_cons` | 2 |
| 4象限で位置づけを示す（軸を自由に決める） | `matrix` | 4 |
| SWOT分析 | `swot` | 4固定 |
| 選択肢を複数の基準で評価する（◎○△×） | `comparison_matrix` | 行6×列5まで |
| 責任分担を示す | `raci` | 行6×列5まで |
| 手順・ステップを横に流す | `process` | 3〜6 |
| 循環・PDCAを示す | `cycle` | 3〜6 |
| 分岐のあるフローを示す | `flow_branching` | 分岐2〜3 |
| 定性的な絞り込みの段階を示す | `funnel_steps` | 3〜5 |
| 上位ほど小さい階層を示す | `pyramid` | 3〜5 |
| 親子の分解（ロジックツリー）を示す | `tree` | 子2〜5 |
| 多段の組織図を示す | `org_chart` | 10ノード・3階層まで |
| 掛け算・足し算で構造を示す | `formula` | 項2〜4 |
| 2つの集合の重なりを示す | `venn2` | 2 |
| 顧客・競合・自社（3C）を示す | `3c` | 3固定 |
| ファイブフォース分析 | `five_forces` | 5固定 |
| ビジネスモデルキャンバス | `bmc` | 9固定 |
| カスタマージャーニーを示す | `journey_map` | 段階3〜6×行3〜4 |
| 市場規模（TAM/SAM/SOM）を示す | `tam_sam_som` | 3固定 |
| レーン別のロードマップを示す | `roadmap` | レーン4・各4施策まで |
| システム構成を左→右の層で示す | `cloud_architecture` | 2〜6層 |
| 技術スタックの層を示す | `layered_stack` | 6層まで |

### 分類B: 要素間に関係がない（データ・事例）

| したいこと | 識別子 | 要素数 |
|---|---|---|
| 指標（KPI）を並べる | `kpi` | 1〜4 |
| 単一系列の量を比較する（順位なら横棒） | `bar_chart` / `bar_horizontal` | 項目12まで |
| 複数系列を比較する | `clustered_bar` | 系列3まで |
| 時系列の推移を示す | `line_chart` | 系列3まで |
| 内訳の積み上げ・構成比の推移を示す | `stacked_bar` / `stacked_100_bar` | 系列4まで |
| 増減の要因分解を示す | `waterfall` | 段階3〜8 |
| 目標に対する達成度を示す | `bullet` | 1〜4本 |
| 段階的なコンバージョンを数値で示す | `funnel` | 6段まで |
| 2変数の相関を示す | `scatter` | — |
| 特定の棒に注釈を付けて示す | `annotated_chart` | 注釈1〜2 |
| 年表・沿革・スケジュールを示す | `timeline` | 3〜7 |
| 事例・特徴・メンバーを並べる | `cards` | 2〜6 |
| 料金プランを比較する | `pricing_tiers` | 2〜4 |
| 表で整理する | `table` | 行8×列6まで |

### 分類C: ページ項目が決まっている

| したいこと | 識別子 |
|---|---|
| 表紙 | `title` |
| 章の扉 | `section` |
| 目次・アジェンダ | `agenda` |
| 巨大な数字1つを主役にする | `big_fact` |
| 数字3つを並べる | `stat_trio` |
| 宣言文・一言メッセージ | `statement` |
| 引用・問いかけ | `quote` |
| OKR（目標と主要な結果） | `okr` |
| 振り返り（Keep/Problem/Try） | `kpt` |
| 報告・相談・依頼 | `houkoku_sodan_irai` |
| 持ち帰りポイント | `takeaways_emoji` |
| Q&A | `faq_qa` |
| テキストだけで示す（最後の手段） | `bullets` |

### 使わない表現

- **円グラフ・ドーナツ・ゲージ・3Dグラフ**: 角度や面積は位置・長さより読み取りにくい。
  構成比は `stacked_100_bar` か `bar_horizontal`、達成度は `bullet` で代替する。
- **SmartArt のまま放置**: 使ってよいが、強調1箇所・テーマ色のルールに合わせて色を直す。
  レシピと同じ構造にならない場合は図形で組む。
- **画像の羅列・ロゴの壁・装飾目的のイラスト**: 伝えたい主張に直結しないなら入れない。

## レイアウトのレシピ

全パターン共通の骨格（16:9）:

- **上部**: タイトル（主張）。必要ならタイトルの上に小見出し（章名など）を小さくメイン色で置く。
- **リード文（任意）**: タイトルの下に1行。ボディの読み方を示す。
- **ボディ**: 左右の余白はスライド幅の約5%。ボックス間の間隔は均等にする。
- **下部**: 注釈・出典を10〜11ptのグレーで左下に。

以下、ボディ部分の組み方。「強調」はアクセント色を使う1箇所を指す。

### 比較・対比

- **compare**: 同じ幅の縦長ボックスを2〜4列並べる。各列は上に見出し帯（メイン色地・白文字）、
  下に本文（薄いグレー地）。推奨案だけ見出し帯をアクセント色にする。
- **before_after / problem_solution**: 左右2パネル＋中央に右向きの矢印。左はグレー寄り、
  右はメイン色寄りにして、右（あるべき姿・解決策）を主役にする。
- **before_after_metric**: 左右に大きな数字（48〜60pt）とその下に1行のキャプション。中央に右向き矢印。
  After の数字だけアクセント色。
- **pros_cons**: 左右2列。見出しは「メリット」「デメリット」。記号は使わず、列の見出し色で区別する
  （メリット=メイン色、デメリット=グレー）。

### 4象限・マトリクス

- **matrix**: 2×2の同じ大きさのボックス。左に縦軸ラベル、下に横軸ラベル（低→高）。
  注目する象限だけアクセント色の枠か地色にする。
- **swot**: 2×2。上段が内部要因（強み・弱み）、下段が外部要因（機会・脅威）。左列がプラス、右列がマイナス。
  各ボックスの左上に S/W/O/T の見出し。
- **comparison_matrix / raci**: 表で組む。1行目が評価基準（または役割）、1列目が選択肢（またはタスク）。
  セルは ◎○△× や R/A/C/I を中央揃え。推奨する行だけ地色を薄いアクセント色にする。

### 流れ・時間

- **process**: 山形（シェブロン）または角丸四角形を横一列に3〜6個、間に右向き三角か矢印。
  各ステップの下に短い説明を置く。重要なステップだけアクセント色。
- **cycle**: 3〜6個の円か角丸四角形を円周上に等間隔で置き、時計回りの曲線矢印かコネクタでつなぐ。
  中央にサイクル名を置いてよい。
- **flow_branching**: 左に起点、右に2〜3本の分岐先。分岐の条件はコネクタの横に小さく書く。
- **timeline**: 横線1本の上に、時点ごとの点（小さな円）と日付、その上下に交互に出来事を置く。
  現在や節目の1点だけアクセント色。
- **roadmap**: 表の格子を下敷きにする。1列目がレーン名、1行目が期間（四半期・月）。
  各施策を、期間をまたぐ角丸四角形のバーとして該当レーンに重ねる。
- **journey_map**: 横軸に段階（認知→検討→購入→利用など）、縦に「行動」「思考・感情」「接点」
  「課題」の行を持つ表。課題の行のうち最も重要なセルだけアクセント色。

### 階層・構造

- **pyramid**: 下ほど幅が広い台形（または幅を段階的に変えた四角形）を3〜5段積む。
  最上段が最も重要・最も小さい層。
- **tree**: 左に親、右に子を縦に並べ、カギ型コネクタでつなぐ（ロジックツリー）。
  子が多い場合も1枚では2階層まで。
- **org_chart**: 上から下へのツリー。同じ階層は同じ高さ・同じ大きさのボックスにそろえる。
- **formula**: 項目のボックスを横に並べ、間に「×」「＋」「＝」を大きめの文字で置く。
  右端の結果のボックスだけアクセント色。
- **funnel_steps**: 上ほど幅が広い横長の帯（台形または幅を変えた四角形）を3〜5段、中央揃えで縦に積む。
- **layered_stack**: 同じ幅の横長の帯を縦に積む。上が利用者に近い層。

### フレームワーク

- **3c**: 三角形の頂点に3つのボックス（上=顧客、左下=競合、右下=自社）。
- **five_forces**: 中央に「業界内の競争」、上下左右に4つの力（新規参入・代替品・売り手・買い手）、
  中央に向かう矢印でつなぐ。
- **bmc**: 横5列のキャンバス。上段は左から パートナー／主要活動・リソース（上下2段）／
  価値提案／顧客との関係・チャネル（上下2段）／顧客セグメント。下段はコスト構造と収益の流れの2つ。
- **tam_sam_som**: 大中小の円3つを下端揃えで入れ子にし、各円の上部にラベルと金額を置く。
  最も内側（SOM）だけアクセント色。
- **venn2**: 半透明の円2つを重ね、重なり部分に共通項を書く。

### データ・グラフ

チャートは PowerPoint のネイティブのグラフで作り、元データを編集できるようにする。

- 色はグレーの濃淡＋アクセント1色まで。言いたい系列・棒だけをアクセント色にし、残りはグレーかメイン色。
- 凡例はなるべく使わず、系列名をグラフの線や棒の近くに直接置く。
- 目盛り線は薄く、または無し。必要なら値ラベルを直接付ける。
- グラフのタイトルではなく、スライドのタイトルで「何が言えるか」を書く。

個別:

- **kpi / stat_trio / big_fact**: 大きな数字（44〜60pt）、その下に指標名と前期比などの補足。
  数字が主役なので図形の枠は控えめにする。最も重要な1つだけアクセント色。
- **bar_horizontal**: 順位を見せる場合は値の大きい順に上から並べる。
- **waterfall**: 積み上げ縦棒グラフで、見えない（塗りなし）系列を下に敷いて浮いた棒を作るか、
  四角形を並べて組む。始点と終点の棒はメイン色、増加はメイン色の薄い色、減少はグレー、
  主要因の1本だけアクセント色。
- **bullet**: 横長の帯（薄いグレー）を目標レンジ、その上に細い棒（メイン色）を実績、
  縦の短い線（アクセント色）を目標値として重ねる。
- **funnel**: 段ごとに幅が数値に比例する横長の四角形を中央揃えで積み、右側に転換率を書く。
- **annotated_chart**: 棒グラフに吹き出し図形で注釈を1〜2個だけ付ける。
- **table**: 見出し行はメイン色地・白文字。罫線は横線だけ細いグレーで。数値は右揃え、単位は見出しに書く。
  強調したいセルは1つだけ太字かアクセント色。

### 定型ページ

- **title**: 資料名（大）、サブタイトル、日付・作成者。テンプレートのタイトルレイアウトを使う。
- **section**: 章番号と章名だけ。
- **agenda**: 番号付きの項目を縦に3〜7個。現在の章を強調する用途ならその項目だけアクセント色。
- **statement / quote**: 中央に大きな文字で1〜2行。引用なら下に出典。
- **okr**: 上部の帯に Objective、下に Key Result のカードを2〜5枚並べ、各カードに目標値。
- **kpt**: 3列（Keep・Problem・Try）。Try を主役にする。
- **houkoku_sodan_irai**: 3列（報告・相談・依頼）。聞き手に求めるアクション（依頼）を主役にする。
- **takeaways_emoji / faq_qa / cards**: 同じ大きさのカードを格子状（2〜3列）に並べる。
- **bullets**: 箇条書きは1階層まで、5項目以内、各1〜2行。

## よくある依頼への対応

- 「この資料をスライドにして」: 素材を読んだうえで、ヒアリングは不足分だけに絞り、構成提案から始める。
- 「このスライドを見やすくして」: レビューの3観点で講評し、合うパターンへの置き換え案を示してから直す。
- 「デッキ全体を整えて」: スライドごとにタイトルが主張になっているか、強調が1箇所か、端と間隔が揃っているかを
  点検し、一覧で示してから直す。
- 「グラフにして」: 上記「データ・グラフ」の規則で作り、何が言えるかをタイトルに書く。
